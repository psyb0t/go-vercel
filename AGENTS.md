# go-vercel

Unofficial Go client for the Vercel REST API, generated from Vercel's OpenAPI spec. If you only want to use the client from an agent, read [.agents/skills/go-vercel/SKILL.md](.agents/skills/go-vercel/SKILL.md) instead; this file is about changing the code.

## Architecture

Generation pipeline, declared in `gen.go` and run by `make generate`:

`scripts/fetch-spec.sh` (download `https://openapi.vercel.sh/` to `api/openapi.json`) → `scripts/patch-spec.sh` (jq fixes for what oapi-codegen can't generate) → oapi-codegen with `config.yaml` (writes `client.gen.go`) → `scripts/split-gen.sh` (splits it into `client_NNN.gen.go`, about 20k lines each).

## Stack

- Go 1.26.10, one package `vercel` at the module root.
- oapi-codegen v2, run through `go tool`, with `github.com/oapi-codegen/runtime` at runtime.
- goimports through `go tool`, to drop unused imports from the split files.

## Layout

- `gen.go`, `config.yaml`: generator steps and oapi-codegen config.
- `client_NNN.gen.go`: the generated client. Never edit.
- `client_test.go`, `example_test.go`: hand tests against `httptest` and the README example.
- `scripts/`: fetch, patch and split steps, plus the lint and security scan scripts the Makefile runs.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The generated package is over 500k lines. `make lint` takes about half an hour, most of it in `unused`, so `scripts/lint.sh` uses a 90 minute timeout.
- In a single file, wrapcheck walks the whole file once per returned error and runs for hours. That is why `split-gen.sh` exists. Don't drop it.
- `make dep` before the first `make generate` drops `github.com/oapi-codegen/runtime` from `go.mod`, because nothing imports it yet. Run `make dep` again after generating.
- The spec changes upstream without notice. A regeneration can rename types or break on a new shape; fix it in `patch-spec.sh`.
- CI skips the generate drift check, since the spec moves upstream.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
